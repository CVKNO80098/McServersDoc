服务器在线状态
==============

MC Server Web 当前同时存在两类服务器状态检测机制：后端主动 Minecraft Ping 和 Agent 心跳。

后端主动检测
------------

后端的定时任务会寻找启用了服务器检测标记的服务器，然后尝试连接服务器的 Minecraft 地址和端口。

检测使用 Minecraft Server Ping。连接成功时，服务器的 ``active`` 状态会被设置为在线；连接失败时会被设置为离线。

当前定时任务的执行间隔为 **10 分钟**。

因此：

* ``active`` 是后端主动检测得到的状态。
* 服务器刚刚上线或刚刚离线后，列表中的状态可能不会立即变化。
* 服务器是否启用了 ``serverFlag`` 会影响该定时检测任务是否处理它。

Agent 心跳
----------

Agent 使用以下接口发送心跳：

.. code-block:: http

   POST /room/agent/heartbeat

该接口当前不要求 JWT Bearer 认证。

一个简化的请求示例：

.. code-block:: json

   {
     "roomId": "1",
     "agentVersion": "0.1.0",
     "status": "online",
     "verified": false,
     "verificationLevel": 0,
     "minecraft": {
       "reachable": true,
       "latencyMs": 35,
       "playersOnline": 2,
       "playersMax": 20,
       "version": "1.21.x"
     },
     "virtualNetworks": {
       "provider": "example",
       "interfaceName": "Ethernet",
       "ipv4": "192.168.1.100",
       "up": true
     },
     "timestamp": "2026-09-12T10:00:00"
   }

后端收到请求后，会使用 ``roomId`` 查找对应服务器，并将该服务器的 ``updatedAt`` 更新为服务器当前时间。

需要特别注意的是，当前实现并不会简单地把请求中的 ``status`` 或 ``timestamp`` 直接写入服务器状态字段。心跳请求中的其他字段主要用于接收 Agent 上报的数据结构，目前并不意味着这些字段都会持久化到 ``Server`` 实体。

两种机制的区别
--------------

+----------------+------------------------------+------------------------------+
| 项目           | Minecraft Ping               | Agent 心跳                   |
+================+==============================+==============================+
| 发起方         | 后端                         | Agent                        |
+----------------+------------------------------+------------------------------+
| 主要目的       | 检测 Minecraft 服务可达性    | 检测 Agent 是否仍在运行       |
+----------------+------------------------------+------------------------------+
| 是否需要登录   | 后端内部任务，不涉及用户登录 | 当前不需要 JWT               |
+----------------+------------------------------+------------------------------+
| 检测周期       | 当前约 10 分钟               | 由 Agent 自己决定             |
+----------------+------------------------------+------------------------------+
| 可携带信息     | Minecraft Ping 结果          | Agent、MC、虚拟网络等信息    |
+----------------+------------------------------+------------------------------+

当前实现注意事项
----------------

当前版本的列表接口和单个服务器详情接口在获取服务器状态时并不完全使用同一套逻辑。因此，如果客户端发现列表中的 ``active`` 与详情页显示的即时状态存在短暂差异，不应直接认为数据库数据损坏。

此外，Agent 心跳目前主要承担“房间仍然有 Agent 活跃”的信号作用。后续如果实现正式的服务器验证机制，可以在此基础上增加签名、Token、验证等级以及更严格的状态转换规则。
