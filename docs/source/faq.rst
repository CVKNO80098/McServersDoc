常见问题
========

为什么请求返回 401？
--------------------

通常表示当前接口需要登录，而请求没有携带有效的 JWT。

登录后，把返回的 Token 放入请求头：

.. code-block:: text

   Authorization: Bearer <token>

如果 Token 已经过期，需要重新登录获取新的 Token。

为什么注册和登录不需要 Token？
------------------------------

注册和登录本身就是获取 Token 的入口，因此这两个接口是公开接口。

服务器列表也可以在未登录的情况下访问。

Agent 心跳为什么也不需要 Token？
--------------------------------

当前版本的 ``POST /room/agent/heartbeat`` 被配置为公开接口，因此 Agent 不需要使用用户 JWT 才能发送心跳。

这并不意味着 Agent 已经完成身份认证。对于生产环境，更严格的 Agent 身份验证可以通过独立的 Agent Token、签名或其他机制实现。

服务器列表是不是只显示在线服务器？
----------------------------------

不是。

当前服务器列表接口使用分页查询获取服务器记录，并按照在线状态等条件进行排序；它不是简单的“只查询 active=true”。因此离线服务器也可能出现在列表中。

为什么服务器刚刚上线，页面还是显示离线？
----------------------------------------

后端的主动 Minecraft Ping 检测任务当前每 10 分钟执行一次。因此数据库中的 ``active`` 状态可能存在最多一个检测周期左右的延迟。

如果客户端需要更实时的状态，可以结合服务器详情接口或后续的 Agent 状态机制进行处理。

服务器创建后，为什么不能自己指定 ownerId？
--------------------------------------------

服务器所有者由后端根据当前登录用户确定。这样可以避免客户端伪造其他用户作为服务器所有者。

好友请求为什么不能随便接受？
----------------------------

好友服务会检查当前用户是否是该请求的接收方。只有接收方可以接受待处理的好友请求。

注销以后 Token 会永久失效吗？
----------------------------

当前实现会把 JWT 的 ``jti`` 加入服务端的撤销集合，因此注销后的 Token 在当前服务器进程中会被拒绝。

不过撤销集合目前保存在内存中。服务器进程重新启动后，该内存集合会丢失，因此不能把当前实现理解为持久化的 Token 黑名单。

Token 多久过期？
----------------

当前后端默认 JWT 有效期为 **1440 分钟（24 小时）**。实际部署可以通过后端配置修改。

为什么 Agent 发送了 verified=true，服务器仍然不一定显示“已验证”？
--------------------------------------------------------------

因为当前心跳接口只是接收 Agent DTO，并根据 ``roomId`` 更新服务器的 ``updatedAt``。请求中的 ``verified`` 等字段并不会自动触发完整的服务器验证流程。

因此，“Agent 上报 verified=true”和“后端正式完成服务器验证”是两个不同概念。

如何判断接口是否正常运行？
--------------------------

可以访问公开健康检查接口：

.. code-block:: http

   GET /

该接口可以用于最基础的服务可用性检查。

默认服务器地址是什么？
----------------------

本文档中的示例默认后端运行在：

.. code-block:: text

   http://localhost:8080

如果部署到其他主机或端口，只需要将示例中的基础地址替换为实际地址。
